# Cross-stage research provenance

This collection preserves compact operational receipts, logs, descriptive findings and exact operator-source snapshots connecting the completed computational stages. Use the separate numerical archives for canonical estimates, uncertainty, frozen scientific sources and indexed local raw inputs.

All declared computational stages are verified complete: **90 fits, 792 primary / 948 retained accuracy records, 1,080 joint contrast packets, 696 collocation timing workloads with 156 restorations, and 288 correction timing jobs**. The external collector verified report freshness, current source-bound 1,502-test proof and all required numerical archives. This collection does **not** mark R1–R6 or the overall research goal complete. Owner interpretation, final documentation and public-main/Actions signoff remain pending. Completed computations do not imply blanket accuracy certification or a neural cost advantage.

- `actual/` preserves the joint freeze before final values, all six terminal reference workers and integrity proof, the 72-model validation residual stage, and the original 15-fit/26-file archive checks. The final original-archive receipt confirms unchanged bytes and exact inventory without replacing the earlier receipt.
- `final_computational/` contains the canonical terminal coordinator receipt, its ten successful stage logs, and the successful external collector output/log. The collector deliberately records overall completion as false while computational evidence is complete. Its JSON is checksum/provenance metadata; full banks, weights and caches remain local.
- `operator_sources/` holds exact `nn_dk_actual_final_stages.py` and `nn_dk_collect_readme_final_evidence.py` snapshots. These are immutable, host-specific operator provenance with original absolute paths, not package modules or portable commands to restart work. They have no `__init__.py`. The artifact directory is excluded from Ruff and lies outside the 287 maintained-source QA map; wheels contain `src/nn_dk`, while source distributions include these provenance files. Preserve them without editing or executing them as new scientific work. Python source is MIT licensed.
- `tiny_v2/` retains the separate reduced software fixture and complete fit/lock/reference/accuracy/timing/report/archive acceptance. Its earlier accuracy-only receipt remains incomplete for timing by design; the later end-to-end receipt records software completion. These do not replace the scientific allocation or certify its accuracy.
- `collocation_accuracy/` contains all-seed independent C findings and their residual-to-accuracy descriptive join, including its previously external JSON/Markdown dependency. Finite-reference discrepancies and pointwise qualifications remain explicit.
- `branch_ci_9ceeb7d/`, `branch_ci_3e6e71d/` and `branch_ci_cf6e7da/` preserve successful branch CI receipts and full logs at their exact commits. Their green 1,502-test/Ruff/build results are not final public-main verification.
- `requirements_audits/` preserves the completed R1/publication-provenance review, source-only path/schema audit and preparation requirements draft. The draft remains `complete: false`; it is not execution proof.
- `clean_clone_0112776/` preserves full-history clone, locked install, wheel/source build, documented smoke and wheel import/CLI verification at implementation commit `0112776`. Build binaries remain local. No package-registry publication is claimed.
- `documentation/` preserves the rendering audit and GitHub HTML previews. The full third-party MathRenderer JavaScript remains local; the audit identifies its URL and hash.

The original `actual_joint_freeze.json` retains `complete: false`: prepare/freeze both exited zero, but the outer postcheck logger looked in the wrong location. `actual_joint_freeze_verified.json` corrects that postcheck against `comparison/evaluation_lock.json`, binds the original receipt and verifies unchanged locks before any final values. No numerical work or draw was repeated for the logger correction.

The production residual receipt retains the original generated narrative hash. A maintained narrative may append a separately labeled interpretation; the archived generated report and historical receipt remain unchanged. The final composite must hash the current maintained note separately.

See the current [manifest](manifest.json) for every copied file's original absolute path, byte count and identical source/stored SHA-256. Its root inventory is extensible; all existing copied payloads and submanifests retain their bytes. The README has a separate generated-file digest in that manifest, avoiding a self-hash cycle. Absolute source paths are provenance, not portable input locations.

Process snapshots, dynamic journals, private observer/recovery metadata, third-party renderer source, full banks/checkpoints/NPZ/cache binaries and the private duplicate final-results review are excluded. Any later publication receipts must be stable and must exist before a separate parent-controlled append.
